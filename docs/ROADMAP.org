* Overview

This roadmap tracks Lexicon's evolution from a bare Emacs implementation to a full package ecosystem. Strategy: build a solid, tested core first, then grow the package ecosystem.

Source of truth: [[https://github.com/eprapancha/lexicon/issues][GitHub Issues]]

* What's Been Built

The core editor is substantial:

- Full editing: kill ring, yank, undo, prefix arguments, rectangle operations, keyboard macros
- Buffer/window/frame management with splitting, navigation, tabs
- Minibuffer completion system with styles (basic, substring, flex, orderless) and icomplete
- Major/minor modes with hierarchical keymaps and buffer-local state
- File operations via FS Access API (find-file, save, dired)
- Search: isearch, query-replace, occur, grep
- Programming: compile (stub), imenu, outline, folding, font-lock
- Help system: describe-key/function/variable, info browser
- Diff/merge: diff-mode, ediff, smerge-mode
- Text properties, overlays, markers, narrowing
- Customization: defcustom/defgroup with localStorage persistence

** Package Infrastructure

- Package system: install-package from short names or URLs
- Package registry (lexpa): recipe-based, decoupled from editor and packages
- defcustom/defgroup/custom-set-variables with localStorage persistence
- Unified variable stores (:global-vars canonical, atom mirror)
- SCI sandbox with 230+ API functions
- Dependency resolution and lifecycle management

** Completed Packages

- *Vertico* -- Vertical completion UI
- *Marginalia* -- Rich annotations for completion candidates
- *Orderless* -- Multi-component completion matching (literal, flex, regexp, prefix, initialism, negation dispatchers, smart case)

* Active Work: Completion Ecosystem

Prove that the Elisp compatibility layer works by porting high-value completion packages.

** Up Next

- *Consult* -- Enhanced commands. Buffer-local sources first (=consult-line=, =consult-outline=, =consult-buffer=, =consult-history=). External sources (=consult-ripgrep=, =consult-find=) deferred until WASM ripgrep or backend.
- *Embark* -- Action framework on top of completion candidates (act-on-thing-at-point, bulk actions)

* Future Work

** Tree-sitter (WASM)

Modern syntax highlighting via =web-tree-sitter= WASM integration. Replace regex-based font-lock with proper AST-based parsing.

- Load =web-tree-sitter= and language grammar =.wasm= files
- Incremental parsing on buffer edits
- AST-to-face mapping (tree-sitter highlight queries)
- Major modes backed by tree-sitter (=typescript-ts-mode=, =rust-ts-mode=, etc.)

See [[file:VISION.org][Vision]] for the broader WASM ambitions.

** WASM Core Expansion

Compile C/Rust tools to WASM to reduce backend dependencies:

- ripgrep in WASM (enables =consult-ripgrep= in-browser)
- Emacs regexp engine (=src/regex-emacs.c=)
- Emscripten virtual filesystem as shared substrate
- Selected Emacs C primitives (buffer internals, intervals)

** Package Security

Defense-in-depth for arbitrary package code:

- Content Security Policy headers
- Web Worker isolation (packages in separate threads)
- Capability-based permissions (declared in =package.edn=)

See [[file:VISION.org][Vision]] for details.

** Evil-mode

Full Vim emulation as an external package.

- Modal editing (normal, insert, visual, operator-pending)
- Vim operators and motions
- Ex command line

** Backend Server Bridge

WebSocket bridge to enable features that require server processes:

- Shell/terminal (PTY)
- Version control (git operations)
- LSP (language server communication)
- TRAMP (remote files)
- Compilation (real build commands)
